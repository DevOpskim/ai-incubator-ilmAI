## What was done

- Fixed DNS: EC2 public IP changed (no Elastic IP) → learn.devops.kim was pointing to old IP; resolved by checking new IP
- Switched LLM default provider: Groq → OpenRouter (free model: meta-llama/llama-3.3-70b-instruct:free → nvidia/nemotron-3-nano-30b-a3b:free → google/gemma-4-26b-a4b-it:free)
- Added user-friendly error messages: frontend shows red error banner instead of silently failing when LLM calls fail (plan, quiz, flashcards, chat, gaps endpoints)
- Added retry logic for empty LLM responses in plan generation (retries once on blank response)
- Updated chat provider/model defaults to OpenRouter free models with dropdown options

## Problems encountered

- Generating Plan failed after uploading actual roadmap from roadmap.sh website
- EC2 public IP changed — instance had no Elastic IP; IP changed on stop/start, DNS still pointed to old IP
- Groq rate limit — hit 100K TPD limit on llama-3.3-70b-versatile; needed ~1hr reset
- OpenRouter invalid key — existing API key returned "User not found" (401); needed new key
- OpenRouter insufficient credits — paid models returned 402 error; free models were upstream rate-limited (429)
- Free LLM models unreliable — Nvidia Nemotron returned empty responses intermittently; needed retry logic
- Pipeline deploy failed — SCP step couldn't reach EC2 because old IP was in GitHub secrets
- Free model performance — all OpenRouter free models routed through Venice provider which was heavily rate-limited


## Solutions

- Allocated and associated an Elastic IP to the EC2 instance
- Switched to OpenRouter free models to avoid paid API costs
- Added retry loop for empty LLM responses in plan generation
- Added try/except with user-friendly error messages across all LLM-powered endpoints
- Updated frontend to display error messages in a red banner instead of silent failure


## Next plan

- Migrate to more reliable LLM options: Groq free tier (daily 100K TPD reset) works best when not rate-limited
- Consider upgrading EC2 instance type to run local Ollama models (t3.medium or larger needed)
- Add a Settings page where users can configure their preferred LLM provider/model
- Add image/video file handling to skip them during text extraction (not a real problem currently but good defense)
